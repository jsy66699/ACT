# 反例多样性指标:定义、推导与实现

推导对任意 ReLU 网络 + 任意 ACT 支持的 output spec 都成立。
最初只在 cora_2024(9 个 ReLU 全连接网络,3072→250×7→10 或 784→250×7→10)上实现,
第 8 节把它跑满了四个 benchmark(cora / mnist_fc_v2 / cifar100_2024 / safenlp_2024)。

**实现**:`act/pipeline/Shiyang/pipeline/ce_diversity.py`(`python -m ... ce_diversity all`),
读的是 `--dump-founder-clusters` 写在 `results/div_<bench>/<arm>/<group>/ce_sample.npz` 的转储。

---

## 1. 记号

- 网络 `f: R^d → R^C`,只含 ReLU 非线性,共 K 个 ReLU 神经元
- 输入 `x ∈ R^d`,输出 logits `z = f(x)`,`z_c` 为第 c 类
- 规范:TOP1_ROBUST。给定真实类别 `t` 与输入盒 `B = [x₀−ε, x₀+ε]`,
  性质为 `∀x ∈ B, argmax_c z_c(x) = t`
- 反例 = 满足 `x ∈ B` 且 `argmax_c z_c(x) ≠ t` 的点

定义**违反 margin**

    m(x) = max_{j≠t} z_j(x) − z_t(x)

则 `x` 是反例 ⟺ `x ∈ B` 且 `m(x) > 0`。

---

## 2. 核心事实:一个反例 = 一条线性约束

设 `σ(x) ∈ {0,1}^K` 为 `x` 处所有 ReLU 的开关模式(激活模式)。
在模式固定的开区域

    P(σ) = { x : 所有 ReLU 的符号模式等于 σ }

上,网络是**仿射**的:`f(x) = W_σ x + c_σ`。若在该区域内 `argmax_{j≠t} z_j` 也稳定
(记为 j*),则

    m(x) = a·x + b,   其中 a = ∇ₓ m(x) ∈ R^d,  b = m(x) − a·x

**推论:落在同一区域(且同一 j*)的两个反例,给出的 `(a, b)` 完全相同。**
对"修复"这个下游任务而言,它们施加的是同一条线性约束,因此**近似冗余** ——
其中只有违反幅度最大的那个点是有约束力的,满足它则该区域内其余全部自动满足。

这条推论是整个指标的基础:**多样性应当按 `(a, b)` 的差异来度量,而不是按反例个数。**

计算上,`a` 由一次反向传播得到:

    a = ∂ m / ∂ x   （在该反例处求值）
    b = m(x) − a·x

### 2.1 任意 spec 下的 m（跨 benchmark 必须的推广）

上面把 `m` 写成 TOP1 的 `max_{j≠t} z_j − z_t`,只对 TOP1_ROBUST 成立。
safenlp_2024 的规范是 **BOX_UNSAFE_LINEAR**,根本没有"真实类别"
(转储里 `true_class` 全是 −1),这个式子在那里不是不方便,而是**没有定义**。

推广:令 `m = OutputSpec.severity(f(x), rows=i)` —— ACT 自己的有符号违反边界,
`severity > 0` 即违反,也正是 fuzzer 梯度上升的那个目标。五种 kind 都有定义:

    TOP1_ROBUST     max_{j≠t} z_j − z_t          ← 与上式逐字相同
    MARGIN_ROBUST   m − (z_t − max_{j≠t} z_j)
    RANGE           max(max_k(lb_k − z_k), max_k(z_k − ub_k))
    LINEAR_LE       max_i (c_i·z − d_i)
    UNSAFE_LINEAR   −max_i (c_i·z − d_i)

第 2 节的论证不依赖 `m` 的具体形式,只依赖它在"ReLU 符号模式 + spec 内部那个
argmax 都固定"的开区域上是仿射的 —— 这五种 kind 全都满足。UNSAFE_LINEAR 取到
最大的那一行就是当前起作用的约束,`a` 是它的方向。

**换用 severity 不改动已测的两个 benchmark**:TOP1_ROBUST 上它就是原式。
重跑 cora 得到同样的 D(47/126/105/111)、同一个示例实例,每实例 S 与旧版
差 1e-8(最大 4.7e-6,来自 float32/float64 在次大类别接近并列处的舍入);
mnist 重跑差 1e-7。

## 3. 实例内多样性 S(最终采用)

只保留方向,丢弃幅值:

    â = a / ‖a‖₂

对某个 instance `i` 的 n 个反例,定义**平均两两余弦距离**

    S_i = ( 2 / (n(n−1)) ) · Σ_{p<q} ( 1 − â_p · â_q )

取值范围 `[0, 2]`:

- `S_i → 0`:所有反例给出同方向的约束,完全冗余
- `S_i = 1`:平均而言两两正交
- `S_i > 1`:平均夹角大于 90°

### 3.1 稀疏化(已撤销 —— 当初的理由是错的)

原文写的是:`S_i` 依赖样本量 n,不同 arm 的反例数相差数倍,不控制的话指标会退化为
"谁跑得多谁赢";做法是每个 instance 随机降采样到相同的 `n = 60`,重复 `R = 8~20` 次取均值,
反例数不足 n 的 instance 排除。

**这条前提不成立,已经去掉。** 两两距离的**均值**不是样本量依赖的估计量 ——
它对 n 无偏,降采样只增加方差,不消除任何偏差。会随 n 变化的是 6.1 的 Hill 数
(那才是个有偏估计量),稀疏化是从那个失败设计里继承下来的,换了估计量却忘了撤。

现在的 `S_i` 是**精确值**:该实例转储里的每个反例、全部点对。
在 cora 上精确值与稀疏化值三位小数一致。

连带撤销的还有"每臂至少 60 个反例"的入选条件 —— 那本来只是稀疏化的技术要求。
现在的入选条件是 **≥ 2 个反例**(少于 2 个就构不成点对)。

**仍然要控制的是"和谁比"**:各臂破的实例集不同,所以 3.2 的平均必须在
四臂共同破掉的实例上做(见 8.4,非配对平均会给出相反结论)。
另外,PCA 图的**每个 panel 画同样多的点** —— 250 个点的 panel 挨着 66 个点的 panel,
看起来更散的原因与散度无关。

### 3.2 跨实例聚合

    S(arm) = 各 instance 的 S_i 的**等权**平均

等权的理由:每个 instance 是一个独立规范,地位相同。按反例数加权的话,
反例最多的那个实例会主导整个指标。

---

## 4. 与实例间多样性合起来

    D(arm) = 破掉的 instance 数（distinct），实例**间**多样性
    S(arm) = 上述平均余弦距离，       实例**内**多样性

**这两个数不能相乘。** `D` 是计数(单位:个),`S` 是距离(无量纲,[0,2]),
量纲不同。因此指标是二维的 `(D, S)`,不压成标量。

这一点由数据强制:两个轴会给出相反的排序(四个 benchmark 上都是,见 8.1),压成一个数会把这个
trade-off 藏起来。

---

## 5. 图的画法

对**单个 instance**,把三个 arm 的 `â` 合并成矩阵 `Â ∈ R^{3n×d}`:

1. 求合并均值 `μ = mean(Â)`,中心化 `Ã = Â − μ`
2. 对 `Ã` 做 SVD:`Ã = U Σ Vᵀ`
3. 投影到前两个右奇异向量:`p = Ã · V[:, :2]`
4. 三个 panel **共用**这组基与坐标范围,分别画各自的点

**共用基是必须的**:若每个 panel 各自做 PCA,各自的点云都会被缩放到填满画布,
"谁更分散"变成伪比较。

**用 PCA 而非 t-SNE / UMAP**:后两者会制造出并不存在的簇结构,且随
perplexity / n_neighbors 变化 —— 而"是否成簇"正是图要证明的东西,用会造簇的方法
就成了自证。PCA 线性、确定、无超参数。

必须在轴上标出**解释方差比** `Σ_k² / Σ Σ_j²`。四个 benchmark 的示例实例实测
PC1+PC2 合计为 cora 48.7% / mnist 88.6% / cifar 48.3% / safenlp 63.8%,
即图上距离普遍**系统性低估**真实距离,且低估的程度逐 benchmark 不同
——两张图之间不能比"看起来谁更散"。因此:
**S 是可引用的量化结论,图只是它的可视化。**

## 6. 两个失败的设计(记录下来,避免重走)

### 6.1 约束类别计数(Hill 数)

先把反例按 `(a, b)` 在容差 τ 下聚类(余弦 `1 − â_p·â_q < τ` 且偏移
`|b_p/mean|b| − b_q/mean|b|| < τ`),再取 q=1 的 Hill 数

    A_i = exp( − Σ_k p_k ln p_k )，p_k 为第 k 类占比

**失败原因:τ=1e-4 时 A_i ≈ n**(实测 59.4 / 58.6 / 59.8,n=60),即几乎每个
反例自成一类,指标退化为"数反例"。根因是**约束在这些网络上是连续谱而非离散簇**,
任何阈值要么把一切合并、要么把一切拆开。τ 从 1e-6 扫到 1e-2 时某些组的类数
从 401 掉到 49,说明结果由 τ 主导而非由数据决定。

### 6.2 有效秩

对行归一化后的中心化约束矩阵取奇异值谱 `s`,令 `p = s² / Σs²`,

    effRank = exp( − Σ p ln p )

**失败原因:三个 arm 分别为 8.76 / 8.73 / 9.07,无区分度。**
它测的是"张成了几个维度",而三个 arm 都在 3072 维里张成约 9 维;
差别不在维数,而在**这些方向之间的夹角分布** —— 那正是 S 测的东西。

## 7. 最早的实测结果(cora_2024,三臂,稀疏化版)

**这一节保留的是历史记录,数字已被第 8 节取代**:它是三臂、`n=60` 稀疏化、
更早一次 cora 运行的结果(baseline D=43,而后来两次同配置运行是 47 / 44 / 37 / 39
—— 见 9.2 的重复方差)。当前口径的四臂精确值见 **第 8 节**。

| arm | 配置 | D(distinct) | S(平均) |
|---|---|---|---|

    ce1_cerepl        S = 0.664

### 背景:为什么需要这个指标

同一批运行里,论文现用主指标 violations 给出**相反**的排序:

| arm | violations | 独立突破数 | D |
|---|---|---|---|
| baseline | **135903** | 116 | 43 |

baseline 的 13.6 万个反例只来自 116 次真正的突破(平均一次突破膨胀成 1171 个反例),
按 violations 排名它第一,按实际发现它垫底。在 cifar100 的 13 个配置上,
violations 与 distinct 的 Spearman 相关系数为 **−0.59**。

四个 benchmark、同样的四臂、同样的 60s/组、同一份分析代码。
cifar100_2024 与 safenlp_2024 是这次新跑的(`div_cifar` / `div_safenlp`,各 200 specs / 2 组),
cora 与 mnist 是用新代码重算旧转储(数值与旧版一致,见 2.1)。

**S 现在是精确值**:每个反例、全部点对、不做稀疏化(见 3.1 的订正)。

| benchmark | 指标 | baseline | ce1_cerepl | state_ce1_cerepl | hpgd_ce1_cerepl |
|---|---|---|---|---|---|
| cora_2024 (180) | D | 47 | **126** | 105 | 111 |
| | S | 0.318 | 0.494 | 0.457 | **0.541** |
| mnist_fc_v2 (90) | D | 4 | 12 | 13 | **16** |
| | S | 0.355 | 0.549 | 0.485 | **0.592** |
| cifar100_2024 (200) | D | 2 | **10** | **10** | 9 |
| | S | *0.019* | *0.015* | *0.012* | *0.023* |
| safenlp_2024 (200) | D | 6 | **127** | 104 | 99 |
| | S | 0.022 | 0.031 | 0.018 | **0.053** |

*斜体 = 不是测量值,见 8.3。* 图:`results/fig_ce_diversity_4arm_all.png`
(跨 benchmark),以及每个 benchmark 各自的 `fig_ce_diversity_4arm_<bench>{,_S}.png`。

### 8.1 两个轴给出相反排序 —— 现在是四个 benchmark 而不是一个

第 4 节"两个轴会给出相反的排序"此前只有 cora 一个证据。四个 benchmark 后:

```
D 的冠军    cora: ce1_cerepl   mnist: hpgd   cifar: 平局   safenlp: ce1_cerepl
S 的冠军    cora: hpgd         mnist: hpgd   cifar: (hpgd) safenlp: hpgd
```

**HPGD 在四个 benchmark 上都是 S 最宽的那一臂**,而它在 D 上四次里三次是负的
(cora 126→111、safenlp 127→99、cifar 10→9,只有 mnist 13→16 为正)。
这与 `EXPERIMENT_LOG` 里"HPGD 两负一正、不能写成一般结论"**并不矛盾**:
那条结论说的是 D,这里说的是 S,而这正是不把两个轴压成一个标量的理由。
逐实例看也一致:hpgd 在 cora 40 个共同实例里赢 22 个、safenlp 5 个里赢 3 个。

### 8.2 S 的绝对量级把四个 benchmark 分成两族

```
cora / mnist      S ≈ 0.32 – 0.59      约束方向张开
cifar / safenlp   S ≈ 0.01 – 0.05      约束方向近乎平行
```

safenlp 这一族的读法很硬:`ce1_cerepl` 破了 **127** 个实例(几乎是全部可破的),
但每个实例内部的反例给出的约束方向平均夹角只有 **14°**
(S=0.031,取值域 [0,2];`1 − cos 14.3° = 0.031`。作为对照,cora 的 0.494 是 60°)。
**实例间覆盖已经打满,实例内几乎完全冗余。**
这是 S 第一次给出 D 完全看不见的信息:按 D 排,safenlp 已经"做完了";按 S 排,
它每个实例只贡献了约一条线性约束。

### 8.3 cifar100 在 60s 预算下测不出 S(这是本次整合的缺口)

cifar 的四臂 D 是 2 / 10 / 10 / 9,但制导臂的**反例总数**只有 144 / 56 / 61 条
(baseline 是 1,111 条,全砸在 2 个实例上):它们每破一个实例只拿到几个反例。S 是实例内的两两距离,一个只有 2 个反例的实例
只贡献 1 个点对。共同实例集只剩 **1 个**,其上制导臂只有 10 / 15 / 105 个点对
(baseline 因为一直在同一个实例上打转,反而有 31,125 个)。

表里 cifar 那一行的 S 照样算得出来,但它建立在个位数的反例上,**不能引用**。
分析脚本会把这种情况标出来(`S_too_few_pairs`,图里画成淡色虚线),
不是靠人工记得。

**补法**:cifar 需要更长的预算(tinyimagenet 用的是 600s)才能让每个实例攒够反例。
D 那一行不受影响,60s 下照样可读。

### 8.4 配对 S 与非配对 S 会打架 —— 只有配对的那个能做因果

每臂破的实例集不同,所以有两种平均法,脚本两个都报:

```
              S(paired) 只在四臂都破的实例上   S(own) 各臂在自己破的实例上
mnist  baseline   0.355                        0.355   (4 个实例)
       state      0.485                        0.246   (13 个实例)
       hpgd       0.592                        0.267   (16 个实例)
```

**同一批数据,两种平均给出相反的结论。** 原因不神秘:制导臂多破的那些实例
本身反例更少、内部更冗余,把它们平均进来就把均值拉下去了 —— 这是
"破了哪些实例"的混杂,不是"在同一个实例上更不更宽"的效应。

**配对的那个才是可比的**(第 4 节同一个道理:先控制住比较对象)。
S(own) 只能当覆盖面的描述,不能当臂之间的比较。cora 上同样的模式
(hpgd 配对 0.541 / 非配对 0.421),safenlp 上方向相反(0.053 / 0.069),
所以这不是一个可以靠符号规律绕开的问题。

### 8.5 配对集有多小,是这次整合最大的限制

```
benchmark   四臂共同实例数
cora        40
safenlp      5
mnist        4
cifar        1
```

配对集的大小由**最弱的那一臂**(baseline,D = 47 / 6 / 4 / 2)封顶。
换句话说:baseline 越差,能做配对比较的地基越窄。
cora 的 40 个实例是唯一称得上有统计量的;mnist/safenlp 的 4–5 个实例
只能当定性证据;cifar 的 1 个不能用。

**全部四个 benchmark 都是 n=1 次运行**,S 的重复方差仍然完全未测(见 9.2)。

## 9. 尚未解决

1. **无下游验证**:S 目前预测不了任何东西。要成为"发现"而非"定义",需证明
   按 S 挑出的反例做修复,效果优于随机挑选同样数量。
2. **全部 n=1**:同一 baseline 配置跑 4 次,violations 为 73177 / 76207 / 125369 /
   135903(极差 86%),D 为 43 / 44 / 37 / 39(±4)。43→126 这类大结论稳固,
   126 vs 115 这类分辨不出。S 的重复方差完全未测。
3. ~~**n=60 偏小**~~ —— 已解决,稀疏化撤销后 S 是精确值(见 3.1)。
   取而代之的限制是**配对集偏小**:cora 40 / safenlp 5 / mnist 4 / cifar 1(见 8.5)。
4. **未纳入的维度**:区域内极值性(同区域只有违反幅度最大的点有约束力)、
   违反深度(‖x − x₀‖∞ / ε)。
5. **天花板未知**:cora 180 个 instance 中已证实至少 127 个可破(找到反例即证明),
   其余 53 个是否 UNSAT 需跑验证器确认。safenlp 同样未知
   (`results_safe_nlp.csv` 不存在,abcrown 缓存只覆盖 200 个里的 20 个);
   cifar100 已知天花板 29(abcrown: 29 SAT / 100 UNSAT / 71 timeout of 200)。
6. **cifar100 的 S 缺一次更长预算的运行**:60s 下制导臂每实例只有几个反例,
   S 无法测(见 8.3)。要补的是 600s × 4 臂(约 90 分钟),D 那一行不用重跑。
7. **HPGD 赢 S 但输 D,机制未解释**。四个 benchmark 一致,但没有证据说明
   为什么"往不稳定神经元的翻转方向搜"会加宽约束方向而不增加破掉的实例数。
