## 0. 指标与天花板

**主指标 `distinct_instances_hit`**：一次 trial 攻破的**不同实例**数，两组相加。

**天花板 29**，不是 200。alpha-beta-CROWN 在同样 200 个实例上的判定
（`results/abcrown_2025_cifar100_2024_results.csv`）：

| 模型 | SAT | UNSAT | timeout |
|---|---|---|---|
| resnet_medium | 14 | 52 | 34 |
| resnet_large | 15 | 48 | 37 |
| **合计** | **29** | **100** | **71** |

（此前记录的 101 UNSAT 把 CSV 里一行 `test_nano.vnnlib` 也算了进去，已更正。）

**验证过的一致性**：所有臂在所有 trial 里攻破的每一个实例，都落在这 29 个 SAT 里 ——
0 个 unsat 被"攻破"（无假阳性），0 个 timeout 被啃下（尚未超越 abcrown）。
CSV 行序与 `spec_row` 对齐（medium 第 0 行正是组名里的 `prop_idx_7641_sidx_1041`）。

**反例数量不是发现量，是冗余度。** 每攻破一个实例吐出的反例数（CE/distinct）在
baseline 是 477，在最好的臂是 60。CE 总数在不同臂上双向变动，而 distinct 单调。
**不要把 violation 数当战绩报。**

## 1. 发现并修复的缺陷

### 1.1 调度饥饿（有效修复）

`SeedCorpus.select()` 从**扁平全局池**按能量抽样，能量只有 `admitted*10 + violation*100`
clamp 到 0.1 四个取值，且**从不剪枝**。一个被攻破实例的 CE 后代滚雪球，实测占掉
**95% 的采样质量**（3 个实例贡献 2251 个 CE 种子），被饿死的实例再也抽不到。
症状：单次 trial 只够到同一个臂 30 次并集的 22%。

修复 `--ce-parent-replacement`：CE 子代若其父代已在 CE 档（energy ≥ 100），
**由子代顶替父代**，按 `parent_id` 一对一（同一父代一批里产出多个 CE 子代时只顶替一次，
其余丢弃，否则是"删 1 加 N"）。`SeedCorpus` 新增 `_alive` 掩码实现删除。
默认关闭，无退休发生时 `select()` 走快速路径、抽样逐次相同。

### 1.2 coverage 准入的作用域错误（有效修复）

`GlobalCov` 的"已覆盖"是**全批并集**：一个样本算 interesting，条件是它点亮了
**全批历史上从没点亮过**的神经元。于是实例 A 在第 3 次迭代点亮的神经元，
永久抬高其余 99 个实例的门槛，且门槛随运行单调上升。
**B=1 时全局并集 ≡ 逐实例，这个缺陷只在批处理下出现。**

后果可测：coverage 臂语料库停在 273 条活种子，state 臂是 3010 条。

修复 `--coverage-per-instance`：`_covered_masks` 变成 `[实例, 神经元]`，
按 lane 的 `original_index` 索引。报出的 neuron coverage 仍取并集，跨臂可比。

### 1.3 不稳定掩码只用了实例 0（修复了，但无收益）

`compute_unstable_mask` 传入整批 `[B,...]` 的输入盒子，实现却只用第一行：

```python
entry_fact = Fact(bounds=Bounds(lb[:1].clone(), ub[:1].clone()), ...)
relu_masks.append(unstable[0])
```

即**用实例 0 的不稳定集指导全部 100 条 lane**。实测：

| | medium | large |
|---|---|---|
| 批掩码 | 951 | 3,225 |
| 逐实例掩码（自己的盒子） | 均值 922（590-1222） | 均值 2,562（1369-3764） |
| 实例自己的集合落在批掩码里 | **12.2%** | **9.1%** |
| 实际符号翻转落在掩码内 | **7.7%** | **6.6%** |

区间传播是可靠过近似，若掩码对应这条 lane 自己的盒子，掩码外的翻转在数学上不可能
（变异被 `_project` 夹在盒子里）。**86-92% 的翻转发生在掩码外，就是掩码属于别的盒子的铁证。**

修复：`--unstable-mask {row0,union,per_instance}`。`per_instance` 把并集当定宽坐标轴，
另用 `[实例, C]` 子掩码在两处生效 —— 挑翻转候选、打指纹前把自己控制不了的位置钉成常数。
`compute_per_instance_masks` 一次分块传播拿到全部 B 个掩码（朴素写法是"把第 i 行广播成 B 份、
只留第 0 条"，那是 100 倍的冗余，400 秒 vs 1.2/4.0 秒）。

**HPGD 命中率 row0 9-14% → union 7% → per_instance 72-76%。distinct 不动或略降。**

### 1.4 过程性错误（记录以免重犯）

- **补丁脚本逐条写盘、中途断言失败** → 前半落地后半没执行，`CoverageTracker.update`
  少了 `rows` 参数而调用方已在传，**所有臂当场崩**。只跑 `ast.parse` 发现不了签名不匹配。
- **重构后的 import 路径全错**（`back_end.domains.abstract` 等不存在），被
  `except Exception: return None, "back_end_import_failed"` 静默吞掉，
  而 fuzzer 遇到 `unstable_mask=None` **会回退到"全部神经元都是候选"继续跑**。
  正确路径：`back_end.core` / `back_end.layer_schema` / `back_end.verifier` /
  `pipeline.verification.torch2act`。
- **TaskStop 只杀 bash 外壳**，等待中的脚本存活并自行启动了第二个 30-rep 跑，
  与另一个跑写进同一目录 → 数据作废重跑。停后台任务后必须查残留 python 进程。
- **Windows 260 字符路径上限**：臂名 `statehpgdonly_cerepl_perinst` + 95 字符的组目录名
  + `\group_summary.json` 超限，`mkdir` 成功而写文件失败。臂名要短。
- **目标计算放在 `_fuzz_iteration` 里每轮执行**，而 `MutationEngine` 每轮只抽一个策略
  （HPGD 占 1/3~1/2），**2/3 的计算白付，吞吐掉 21%** → A/B 不匹配。
  改成 `target_proposer` 回调，HPGD 真被抽中才算。

## 2. 有效的改动

```
cerepl（调度）           statebase  6.77 → 11.23   t=+10.33 (df=56.8)
                         baseline   3.57 →  7.40   t=+10.75 (df=50.1)
                         statehpgd  6.37 → 10.50   t= +5.04 (df=19.5)
逐实例 coverage（准入作用域） baseline 3.57 → 5.50   t= +5.85 (df=53.3)
```

**cerepl 在三个完全不同的底座上增益是同一个常数（+3.83 / +4.46 / +4.13）**，
与 admission 模式、与 portfolio 里有没有 HPGD 都无关。前两对的 union 是严格超集（一个没丢）。

**作用域 vs 信号的分解**（baseline → 逐实例 coverage → state 准入）：

```
per-trial:   3.57 →(作用域 +1.93)→ 5.50 →(信号 +1.27)→ 6.77     作用域 60% / 信号 40%
union@20:   13.21 →(作用域 +7.91)→ 21.12 →(信号 -0.76)→ 20.36   作用域 100% / 信号 -
```

**在 reach 上，逐实例 coverage 反超了 state 准入。** 原本想立的
"激活模式是比神经元覆盖率更好的信号"这个论点，证据不支持；该立的是
**"批处理让调度和准入的作用域出错，而这个错误在 B=1 时不存在"**。

### 3.1 为什么新颖性判据会失效

准入问"这个受限符号模式见过没有"，只有当状态空间**粗到能被重访**时才有信息。
每 trial 约 4000 个样本：

| 掩码 | 每 lane 可变维度 | 已见过率 | 收录 |
|---|---|---|---|
| row0（原版） | ~116 / ~293 | 20-27% | 73-80% |
| per_instance | ~883 / ~2688 | 0.0% | ~100% |
| union | 18,396 / 82,196 | 0.0% | ~100% |
| per_instance + 10 维 | 10 | 55.7% | 44% |

**那个 bug 意外制造了一个低运动量投影，而这正是新颖性判据需要的。**
row0 的 116 维之所以有 20-27% 碰撞，不是因为维度低（2^116 仍远大于 4000），
而是因为**它看错了地方** —— 92% 的实际运动在它视野之外，指纹在一个几乎静止的投影里看世界。

拒绝率与坐标运动量单调相关：row0（别人的神经元）22.7% > 随机 9.9% > 全留 4.1% > 最常翻 3.5%。
但 `flip_rare`（故意挑最少翻的）拒绝率没升（9.1%）—— 因为"平衡度"是在盒子里**均匀采样**测的，
而实际变异是 PGD 驱动的对抗方向，两个分布差太远，均匀采样对实际运动量没有预测力。

### 3.2 HPGD 目标可行性（做对了机制，没换来结果）

`HPGDMutation` 独立翻转 k 位命名的目标是**可能不存在的符号赋值**（空多面体）。
配对测量（每臂每组 ~1000 样本，同一投影器、同一批 seed）：

| 臂 | d | 命中 | 精确到达 | 落点新颖 |
|---|---|---|---|---|
| interp_0.5（两个真实状态之间） | 7.3 / 16.4 | 100% / 99.5% | **99.8% / 94.0%** | 99.6% / 100% |
| synth_k10（生产） | 10 | 11.6% / 8.0% | 0% / 0% | 98.4% / 99.9% |
| real_cross（别的实例的真实状态） | 196 / 729 | 15.0% / 8.0% | 0% / 0% | 100% |

生产配置的 `residual/d = 1.28 / 1.70` —— **跑完比出发时离目标更远**。
而落点新颖率生产配置本来就有 98-100%：**新颖性早已饱和，不是瓶颈。**

**跨实例目标不可迁移**（同样权重、同样 eps，但输入盒子不同 → 可实现的符号模式集合不同），
命中率与随机拼的目标无异 —— 这堵死了"用别的实例的反例做定位"这条路。

### 3.3 一个错误的测量与它的更正

曾用"单步 HPGD 后查违反"来测 CE 引导翻转的攻击成功率，得到 42.7% / 72.1%，
看似 CE 引导优于随机。**加上起点对照后全部作废**：

```
start=corpus     起点违反率 56.3% / 67.9%   →   NEW（起点不违反者的新违反率）= 0.0%
start=original   起点违反率  0.0%           →   NEW = 0.0%（n=424/324）
```

large 组 retain=100%：所谓"攻击成功"其实是"没跑出违反区域"。
更重要的是**这个测量本身问错了问题** —— HPGD 在流水线里的职责不是一步翻出反例，
而是把搜索挪到别处让 PGD 接着攻，单步查违反考核不到这件事。

## 5. 结论

1. **决定成败的是资源调度，不是搜索方向，也不是状态表示。**
   两次针对"谁拿到搜索预算"的修复都显著有效（+4.47 / +1.93）；
   十二次针对"往哪搜"和"怎么记录搜过哪"的改动全部无效或负向。

2. **批处理引入了 B=1 时不存在的缺陷。** 调度饥饿、coverage 全局并集、
   掩码取实例 0 —— 三者都是"跨实例干扰"，在单实例上自动消失。
   这是比"激活模式是更好的信号"更站得住的论文主线，且有三份独立证据。

3. **新颖性判据的粒度可以从 3.5% 调到 55.7% 的拒绝率，输出不变。**
   状态表示这个旋钮不连着结果。

4. **符号模式的新颖性与"能否违反属性"没有可用的相关性。**
   落点新颖率早已 92-100%，把制导做得更准（命中 9% → 72%、精确到达 0% → 94%）
   一次也没换来更多 distinct。

5. **反例信息不可跨实例迁移**（盒子不同），而同实例的反例又要求"已经攻破"，
   所以 repair 那边的 fault localization（SBFL / Arachne / CARE，都是 failing-vs-passing 对比）
   无法自举。唯一 CE-free 且属性相关的候选是验证器自己的分支打分
   （BaBSR，`act/back_end/bab/branching/`，"三角松弛面积 × |ν|"）—— **尚未尝试**。

6. **原论文（ASE 2026, arXiv 2606.25239）解决的是执行层**（张量批处理 + 自适应扰动尺度，
   40× 吞吐 / 4× violations），**没有触及制导层**。其 batch 定义为"同一模型上的 B 个规格实例"，
   与实现一致（按 `id(pytorch_model)` 分组），不是实现窄化。
   `sat_relu`（100 实例 / 100 模型）是天然的 negative control：那里每组 B=1，
   本文所有效应都应当消失。

## 6. 未完成 / 待确认（部分已由第 7-9 节回答）

- **`prior10`（10 维 + CE 先验）跑到 3/5，13.33 ±0.58，覆盖实例攻破率 0.633**
  —— 全场最高，且 medium 组 10.00 远高于 `base_r10` 的 7.20。
  **这是今天唯一一个正向信号**，n=3 必须跑满再定。若成立，说明
  "低维 + 任务相关坐标"两个条件缺一不可（单独低维 11.60、单独先验 10.60 都无效）。
- **`pgdonly_state` / `pgdonly_cov`（`--pgd-only`，组合 = {pgd 1.0}）已排队**，
  对照 `statebase_cerepl` 11.23 与 `baseline_cerepl` 7.40。
  回答 boundary/random 那 50% 预算有无产出。
- **CE 先验打分公式过于粗糙**：`|P(+|CE) − P(+|非CE)|`，不含样本量。
  large 组的 8 个实例 `n_ce` 只有 4-16，top-k 很可能是噪声。
  两比例 z 统计量 `|p_ce − p_non| / sqrt(p̄(1−p̄)(1/n_ce + 1/n_non))` 是便宜的改法。
- **只在 cifar100_2024 上做过。** 原论文有 3 个 benchmark / 6 个网络。
  safenlp 至少要补一个，否则"批处理制导缺陷"是否普遍成立无依据。
- **71 个 abcrown timeout 从未被碰过。** 目前所有成果都在它已判定的 29 个 SAT 之内。
- `HPGDMutation` 的损失是纯符号 hinge（`self.margin=0.01` 是预激活余量，
  **不是属性 margin**），从不查看输出属性。加一项属性 margin 是唯一没试过的、
  能让模式搜索与反例发现挂钩的改法。

独立分支，其他配置的权重不变（验证过 baseline 仍 .5/.2/.3、absorb 仍 .5/.5）。

| arm | n | distinct | med | lg | iters | distinct/千次迭代 |
|---|---|---|---|---|---|---|
| statebase_cerepl（pgd .5 / bnd .2 / rnd .3） | 30 | 11.23 ±1.55 | 7.47 | 3.77 | 4107 | 2.735 |
| **pgdonly_state（pgd 1.0）** | 5 | 12.00 ±1.41 | 8.00 | 4.00 | **2100** | **5.714** (2.09×) |
| baseline_cerepl（coverage 准入） | 30 | 7.40 ±1.63 | 5.20 | 2.20 | 4310 | 1.717 |
| **pgdonly_cov（pgd 1.0）** | 5 | 7.00 ±1.00 | 4.60 | 2.40 | **2120** | **3.302** (1.92×) |

```
state 准入     +0.77  t=+1.11 (df=5.7)   不显著
coverage 准入  -0.40  t=-0.74 (df=8.1)   不显著
```

**distinct 上两种准入都不显著，但单位迭代产出稳定翻倍（2.09× / 1.92×）。**
准确的结论不是"纯 PGD 更好"，而是：**boundary + random 那 50% 的预算买到的是零** ——
它们让迭代数翻倍（几乎零成本），distinct 却没有相应增加。60 秒预算花在它们身上
和花在 PGD 身上，产出相同。

**固定时间 vs 固定迭代次数会给出不同答案**：固定迭代下纯 PGD 明显胜出，
固定 60 秒下两者打平（PGD 单次贵 50 步梯度，省下的迭代没能全部转化成更多攻破）。
论文里要说清用的是哪个口径。

至此三个非 PGD 策略全部为负贡献：

```
boundary + random  50% 预算  →  拿掉后 +0.77，且省一半迭代
hpgd_cov           33% 预算  →  4.20 / 4.30，几乎等于 baseline 3.57
hpgd               33-50%    →  10.27-10.50，不如不用的 11.23
```

（两个 pgd-only 臂均已跑满 5 reps。）

## 9.3 单实例反例的几何结构 —— 为什么制导必然失败

`--dump-ce-patterns` 导出原始 pattern，`results/analyze_ce_patterns.py` 分析
（3 reps 采集，medium 9 个实例 / large 7 个实例有反例）。

| inst | n_ce | distinct | CE 内部散度（均/最小/最大） | CE↔非CE 距离 | signature |
|---|---|---|---|---|---|
| medium 26 | 188 | **188** | 46.6 / 1 / 96 | 95.2 | 9 |
| medium 39 | 269 | **269** | 29.5 / 1 / 65 | 47.5 | 19 |
| medium 61 | 431 | **431** | 47.5 / 1 / 101 | 83.5 | 32 |
| medium 69 | 102 | **102** | 40.7 / 2 / 73 | 97.8 | 70 |
| large 18 | 24 | **24** | 99.9 / 2 / 164 | 142.0 | 42 |
| large 83 | 51 | **51** | 79.5 / 1 / 157 | 90.2 | 16 |

（坐标轴 C = 18,396 / 82,196。`signature` = 在所有反例上符号恒定、
且与非反例不同的神经元数。）

**1. `n_ce == distinct`，无一例外。** 431 个反例就是 431 个**不同的**激活模式。
反例不聚在一个线性区域里，而是散布在成百上千个互不相同的区域中。
**不存在一个可以瞄准的"反例区域"。**

**2. 两个总体几乎不可分。** 跨总体距离只有各自内部散度的 **1.1-2.0 倍**
（inst 83 是 90.2 vs 79.5，比值 1.1）。不是两个可分的簇，是两团互相渗透的点云；
反例之间最小距离常常是 **1**（只差一个神经元）。
**符号空间里没有可导航的边界。**

**3. 判别性签名只占 0.04%-0.5% 的维度，且随样本量增多而消失**：
`inst 26`（188 个反例）signature 只有 9，`inst 14`（1 个反例）有 449 ——
后者纯粹是"只有一个样本所以什么都恒定"的假象。

### 结论：十二次改进无效有统一的几何解释

HPGD 的前提是"把输入推向某个目标激活模式就能接近反例"。而实测的几何是：
反例散布在几百个不同区域、与非反例交织、无稳定签名。
**不是目标选得不好、不是掩码错了、不是坐标维度不对 ——
符号模式空间里根本没有指向反例的结构可循。**
十二次改进都在优化一个不存在的信号。

这也解释了 `prior10` 的 medium/large 分裂：medium 那几个 n_ce 上百的实例
signature 有 9-70 个，top-10 恰好能抓到一点真信号；large 的 n_ce 只有个位数，
signature 全是样本量假象。

注意能量是**加法**的：`--ce-energy e` 给出四档 `{plain 0.1, admitted 10, CE e, CE+admitted 10+e}`。

"CE 从低于普通种子扫到略高于"，与出厂值 100（十倍于普通种子）之间是断开的。

### 12.3 state 准入的效应会变号（本节最重要的结果）


—— **拒绝样本**，而被拒绝的样本里有用的东西。

这比"新颖性判据无效"强：**它不是无效，是有害。**

## 13. 第三个 benchmark：mnist_fc_v2（2026-08-29 凌晨，n=30）

**这一节里 HPGD 第一次为正，而且这份数据在修好 13.1 那个缺陷之前根本测不出来。**

（`--hpgd-weight 0.5` 给出 33.3% 的 hpgd 份额）。

### 13.1 先修好的缺陷：纯 MLP 图丢失不稳定掩码

`TorchToACT` 的输入层按 `_prod(input_shape)` 分配变量，**含批次维**。
CNN 在第一个 conv 处按 `out_c*out_h*out_w` 重新分配、把批次维扔掉；
而 MLP 的 flatten 用 `_same_size_forward()`，**把 B×784 原样带下去**，
可它记录的 `output_shape` 又是逐样本的。于是 `tf_flatten`
（`act/back_end/interval_tf/tf_cnn.py:313` 和 `:323`）那两道断言无论怎么喂都有一道过不去：

```
传 B 行        → out_vars 长 B 倍          炸 :313
折成 1 行      → output_shape 对不上        炸 :323   ← §11.4 那个"卡在第二道"
```

而 fuzzer 遇到 `unstable_mask=None` **会回退到"全部神经元都是候选"继续跑**，
所以 `--admission-mode state` 在纯 MLP 上根本不是它宣称的东西。

修复：`_per_sample_forward(output_shape)` 按 `_prod(output_shape[1:])` 分配，
两处 flatten 改用它（`start_dim=0` 那种把批次也压平的真·批次混合操作保持原样）。
**B=1 时与旧行为逐字节相同**，验证器自己建的单实例图不受影响。

修复后的实测：

```
mnist-net_256x2     56/512  (10.9%)
mnist-net_256x4    685/1024 (66.9%)
mnist-net_256x6   1184/1536 (77.1%)
```

**影响面不止 mnist**：任何带 Flatten 的纯 MLP benchmark（tllverifybench / cora 之类）
在 B>1 时的 state 臂之前都是退化的。safenlp **没有**中招 —— 它的输入是 (1,30)，
本来就是平的、没有 Flatten 层。

### 14.1 四档里有一档在 gated 模式下不可达

```python
interesting_mask = violation | admitted        # 门（state 分支）
energies = admitted*10 + violation*100         # 标价
energies = clamp(energies, min=0.1)
```

`admitted=False, violation=False` 的样本，门那里就是 False —— **那个 0.1 算出来了但从不入库**。
`coverage` 分支同理（`violation | cov_interesting`）。

**0.1 这一档只有 `--admission-mode always` 才会被填充**，因为它把门写死成全 True。
这解释了 always 臂那个数字：放进 41,808 条非 CE 种子，只换来 53 次抽取。

gated 臂的池子里实际只有：`10`（新颖非反例）、`100`（反例、模式已见过）、
`110`（反例且新颖）、`1.0`（初始种子，每实例一条）。

### 14.2 11.2 的措辞要改：差的是数量，不是单价

11.2 写的是"coverage 饱和后多数种子停在 0.1 地板，state 给 96% 的样本赋 10"。
**对 `always` 成立，对 `baseline` 不成立** —— coverage 的门同样要求 `cov_interesting=True`，
能进来的非反例也是 10 分。

mnist 实测：

```
baseline    live 53,841   非 CE   162 条 × 10     coverage 判据饱和，几乎没有非反例进得来
statebase   live 56,700   非 CE 3,628 条 × 10     22 倍
```

safenlp 同样：baseline 的池子里非 CE 只有 218 条，约等于 200 条初始种子本身。

所以两条通道要分开说，看跟谁比：

```
baseline → statebase   收录通道：放进来的非反例多 22 倍，单价都是 10
always   → statebase   标价通道：数量相近，单价 0.1 vs 10
```

结论方向不变（state 准入增加了非 CE 的采样质量），但 11.2 的机制描述按上面订正。

### 14.3 `rej%` 读不出"新颖性拒绝率"

门是**或**：反例哪怕模式早就见过也照样进，新颖性判据没机会拒绝它，
而 `admitted` 的值算完就扔了、从没被计数。所以 §4/§8 的
`rej% = 1 − (rows − B)/iterations` 只能给一个很松的区间。mnist `statebase`：

```
iterations 89,057   进池 56,700（其中 53,072 是反例）   丢弃 32,357
新颖性拒绝率 ≥ 36.4%（只算非反例那部分）
             ≤ 96%  （假设 53,072 条反例全被判不新颖）
```

要收紧只需在运行器加一行 `len(fuzzer.state_manager._registry)`
（`observe_batch` 每收录一条就 append）。**未加** —— 加了会让同一批 8 格里一半有一半没有。

另外 `rej%` 还把三种丢弃混在一起：准入拒绝、哈希去重、以及 cerepl 的
"同一父代一批只顶替一次、其余丢弃"。第三项只在 cerepl 臂上存在且随反例产量变化
（mnist `baseline` rows=53,841 vs `baseline_cerepl` rows=21,386，准入判据完全相同）。
**cerepl 臂之间、以及与非 cerepl 臂之间的 rej% 都不可比。**

### 14.4 拒绝率与结果无关，这条第三次成立

| benchmark | rej% 跨度 | distinct 跨度 | 关系 |
|---|---|---|---|
| cifar（§4/§8 + bench 臂） | 0.0% – 92.8% | 9 – 12 | 无 |
| safenlp | 2.2% – 61.4% | 10 – 127 | 无（最好的臂 61.4%，次好的 20.3%）|
| mnist | 31.0% – 83.8% | 4.67 – 13.60 | 无（13.00 在 83.8%，13.60 在 45.2%）|

**有信息的是"权重怎么分"（CE 占质量），没信息的是"收了多少"（拒绝率）。**
（曾在只看 mnist 前六个臂时以为存在单调关系，加上两个 ce1 臂后不成立。）

4. **难度分层**：18 个 sat 里 256x2 占 11 个，我们单次就能拿 86%；
   真正难的是 6 个 abcrown timeout，一个也没碰。

## 16. 论文的三个 benchmark 补齐，与预算维度（2026-08-29 ~ 30）

### 16.1 原论文用的是 TrafficSigns / Cifar100 / TinyImageNet

arXiv:2606.25239 摘要："three benchmarks, covering six networks and over 400
specifications across TrafficSigns, Cifar100, and TinyImageNet."
所以 safenlp 和 mnist_fc 是我们**额外加的**，traffic_signs 不是第四个 benchmark，

打通两个新 benchmark 的过程里有两条必须记住的坑：

**① 实例列表逐年重新随机采样，判定必须按同库同路径匹配。**

**② 曾用 `relusplitter` 里的同名文件当 mnist 的参照，得出"2 个假阳性"的健全性告警
—— 那是错的。** 网络逐字节相同，但规格是另一批图（label 3 vs 5，784 个像素里

mnist 真正的 ground truth 在 `vnncomp2022_results/alpha_beta_crown/mnist_fc/`，
已存为 `results/abcrown_2022_mnist_fc_results.csv`。

### 16.2 五个 benchmark 的天花板与批次结构

| benchmark | 实例 | 组 × B | 天花板 | 来源 | 网络 |
|---|---|---|---|---|---|
| cifar100_2024 | 200 | 2 × 100 | **29** | abcrown 2025 | ResNet |

### 16.3 TrafficSigns 是二值网络，论文没有察觉

ONNX 算子：`Transpose / Conv / Sign / Add / Reshape / MatMul / Softmax`，
权重张量全部是 `{-1, +1}`。论文称之为 "three quantised CNNs"，
**从未提及 Sign 激活、梯度为零、或任何特殊处理**，权重也是全局固定的
（"all parameters are held constant across configurations"）。

后果有两条，论文都没讨论：

- **`gradient 0.5` 的预算在这个 benchmark 上空转** —— sign 的梯度处处为 0，
  PGD 的步长为 0，子代与父代逐字节相同、被去重杀掉。实际干活的只有
  boundary + random 那 50%。
- **Table 4 里那个 "100% Neuron Cov." 是饱和不是成绩。** 我们复现出同样的 1.0
  （cifar 是 0.60/0.65）。coverage 一饱和，`cov_interesting` 恒为 False，
  coverage 制导完全没有信号，fuzzer 退化成"只有反例能进种子池"。
  探路实测：30x30 组 **2,121 个反例只对应 1 个 distinct 实例**。

我们的 baseline 探路（60 秒/组，CPU）：distinct 8/43 = 19%，CE/distinct = 532
（cifar baseline 是 477，同量级）。**没有饱和，有充分分辨率**，是可用的底座；
但 state / HPGD 全部不可用（无 ReLU），只能跑 coverage 家族的 4 格。**尚未跑。**

### 16.4 TinyImageNet：算力与调度的 2x2

单组 B=200，是所有 benchmark 里批次最大的。60 秒（n=30）与 20 分钟（n=5）两个预算：

| | 60 秒 | 20 分钟 | 预算带来的 |
|---|---|---|---|
| baseline | 4.50 ±1.89 | 4.80 ±2.17 | **+0.30** |
| statebase | 6.89 ±2.14 | 9.00 ±2.12 | +2.11 |
| baseline_cerepl | 6.30 ±1.44 | 15.60 ±0.89 | **+9.30** |
| statebase_cerepl | — | 25.00 ±3.54 | — |

**光加 16.5 倍算力：+0.30，等于零。修了调度再加算力：+9.30。两者一起：4.50 → 25.00。**

机制上量到底：60 秒的 baseline 里未攻破实例每 rep 分到 4.4 次抽取，
20 分钟的 baseline **降到 3.6 次** —— 多出来的 17,000 个样本全部变成已攻破实例的
冗余反例（CE 档 740 → 17,338 条，非 CE 档 208 → 211 条，几乎没动）。
而 `statebase_cerepl` 把这个数抬到 7,236 次。

> **在没有调度修复的前提下，增加计算预算会让饥饿更严重，而不是缓解。**
> 这直接回答了"加 GPU 有没有用"：光加算力，收益接近于零。

### 16.6 ce_sibling：cerepl 的一条自带负反馈

新的三项分解（16.7）暴露了一个此前没人量过的浪费：

```
tinyimagenet baseline_cerepl   ce_sibling = 58.6%   每 17,120 个样本丢掉 10,032 个
```

原因是 cerepl 的"同一父代同批只顶替一次"规则遇上**有放回抽样 + 极度倾斜的能量**：

```
live 池 267 条，其中 CE 只有 60 条，CE 占采样质量 95.6%
每批 B=200 -> 落在 CE 档上的抽取 = 191 次，可用槽位 60 个 -> 至少 131 次注定被丢
```

**超载判据 `B x ce_mass` vs `ce_count` 在四个臂上全部预测正确。**
`statebase_cerepl` 之所以能超加性（+20.20 > +10.80 + 4.20），正是因为 state 准入
把 CE 槽位从 60 撑到 680、把每批 CE 抽取从 191 压到 111，**解除了超载**
（ce_sibling 58.6% → 6.9%，入库率 14.4% → 61.6%）。

**cerepl 有一条此前未写下的隐含前提：CE 档的种子条数要能容纳落在它上面的抽取次数。**

### 16.7 三个新计数器

| 字段 | 位置 | 回答的问题 |
|---|---|---|
| `corpus_drops` | `corpus.py` add() | 子代没入库的四种去向：gate / dedup / ce_sibling / added，**严格划分 offered** |
| `corpus_draws_by_instance` | `corpus.py` select() | 每个实例的分支拿到多少次抽取 |
| `state_novelty`（+`_by_strategy`）| `actfuzzer.py` | 新颖性判据自己的正判率，与"违反免拒"分开 |

**都是纯计数，不参与决策、不消耗 RNG。**加它们的动机是此前所有关于饥饿的数字
都是从能量份额**反推**的。三条订正：

- **`rej%` 不是"新颖性拒绝率"。** 门是 `violation | admitted`，反例不管新不新颖都进，
  所以那个数主要在数"有多少样本不是反例"。mnist `statebase` 报 36.4%，真实的
  新颖性拒绝率区间是 [36.4%, 96%]，太松无法用。
- **`ce_sibling` 在 mnist 上是 0.0%、在 tinyimagenet 上是 58.6%。**
  先前据 mnist 得出的"rej% 约等于 gate，两类臂可比"只对 mnist 成立。
- **`baseline` 与 `baseline_cerepl` 之间 3.2 万行的差不是同胞丢弃造成的**
  （ce_sibling=0），是搜索轨迹不同 → `cov_interesting` 命中率不同。

新颖率的第一份直接测量（mnist `hce1_ctl`，三个组同一次运行）：

### 16.8 lane 分配：无放回，以及一处订正

论文 Algorithm 3 line 10 是 "draw B indices with replacement (high-energy seeds
may repeat)"，**全文没有给出理由**，也没有讨论过 B>1 时它变成跨规格的赢家通吃。
新增 `--select-without-replacement`（默认关，Gumbel top-k 加权无放回）。

**订正：这个开关作用于「行」不是「实例」。** 一个实例在池子里有成千上万行，


## 17. 每实例轮转：直接改 lane 分配（2026-08-30）

**这一节把 cerepl / ce_energy 的地位重新定性了。它们是在间接地做一件事，而那件事可以直接做。**

### 17.1 起因：无放回改错了层级

论文按能量**有放回**抽 B 条 lane（Algorithm 3 line 10，未给理由）。先加了
`--select-without-replacement`（抽 B 个不重复的**行**），mnist 上完全无效
（16.00 → 16.20，Gini 0.77 → 0.76，有效实例 4.7 → 4.7）。

**原因是它作用于"行"而不是"实例"**：一个实例在池子里有成千上万行，抽不重复的行
它照样占满 lane。单元测试（实例 0 独占 1,201/1,230 行）：

```
有放回      实例 0 拿走 600/600 lane (100%)   被抽到的实例  1/30
无放回      实例 0 拿走 600/600 lane (100%)   被抽到的实例  1/30
每实例轮转  实例 0 拿走  20/600 lane (3.3%)   被抽到的实例 30/30
```

于是加 `--select-per-instance`：**按实例轮转，能量加权只在实例内部生效**。
每个实例先出一条最好的行，再轮第二条，所以每个实例拿到 floor(B/I) 或 ceil(B/I) 条 lane。
mnist 的 B=30 恰好等于每组的实例数，**每批就是实例的一个排列**。

### 17.2 mnist 三个底座，n=3（天花板 18）

| 底座 | arm | distinct | union | Gini | 有效实例 | 最少抽取 | 破:未破 |
|---|---|---|---|---|---|---|---|
| coverage | base_bs | 5.00 | 7 | 0.95 | **1.4** / 30 | 2 | 5,569x |
| | **base_pi** | **13.00** | 13 | **0.00** | **30.0** | 1,908 | **1x** |
| coverage+cerepl | basecerepl_bs | 10.33 | 12 | 0.91 | 2.2 | 8 | 349x |
| | **basecerepl_pi** | **12.67** | 13 | 0.00 | 30.0 | 2,032 | 1x |
| state+hpgd | statehpgd_bs | 7.33 | 13 | 0.95 | **1.3** | **0** | 2,027x |
| | **statehpgd_pi** | **16.67** | 17 | 0.00 | 30.0 | 1,449 | 1x |

（对照臂是同配置带计数器的重跑；n=30 的历史值分别是 4.67 / 9.60 / 6.83。）

**`statehpgd_bs` 的最少抽取是 0** —— 三次跑里有实例一次都没被抽到过。
`base_bs` 的 256x4 组有效实例数是 **1.0**：全部预算实际上给了一个实例。

### 17.3 这是机制指标和结果第一次同向同量级地动

此前十几次改动全部是"机制指标大动、distinct 不动"（3 节的十二次、16.10 的双向消融）。
区别在于那些改的是**搜索方向**（往哪搜），这次改的是**预算分配**（谁能搜）：

```
有效实例    1.4        2.2          30.0
distinct    5.00      10.33        12.67
                  cerepl        每实例轮转
```

**收益递减很明显**：1.4 → 2.2（+0.8 个实例）换来 +5.33，
2.2 → 30.0（+27.8 个实例）只换来 +2.67。前几个实例的边际价值最高。

### 17.4 cerepl 是轮转的弱近似，两者不叠加

```
baseline               4.67 (n=30)
+ cerepl               9.60 (n=30)   +4.93     间接：削掉反例血脉的能量复利
+ 每实例轮转          13.00 (n=3)    +8.33     直接：强制规定 lane 分配
+ 两者                12.67 (n=3)    +8.00     cerepl 的边际贡献 -0.33（噪声内）
```

**同一个瓶颈的两种解法，直接的更强 1.7 倍，且完全覆盖间接的。**
如果两者修的是不同的东西，就该叠加；实测不叠加，所以 **lane 分配就是瓶颈本身**，
而 cerepl 之所以在四个 benchmark 上全正，是因为它间接地把 lane 分配拉匀了一点
（有效实例 1.4 → 2.2）。

它也让最好的配置变简单了：

```
hpgd_ce1_cerepl   state + hpgd + ce_energy 1 + cerepl    15.47 (n=30)
hce1_nr_interp    再加无放回 + interp_real                16.80 (n=5)
statehpgd_pi      state + hpgd + 轮转                     16.67 (n=3)   <- 少两个开关
```

**一个 lane 分配开关替掉了两个能量层改动，成绩持平。**

### 17.5 代价：并集被锁死

| arm | per-rep | union | 单次/并集 |
|---|---|---|---|
| baseline | 2-6 波动 | 9 | 52% |
| base_pi | [13,13,13] | 13 | 100% |
| statehpgd_bs | 波动 | 13 | 56% |
| statehpgd_pi | [17,16,17] | 17 | 98% |
| hce1_ctl_bs | [15,15,16,16,17] | 17 | 93% |
| hce1_perinst | [16,16,16,16] | 16 | 100% |

**均分消除了随机性，也消除了"偶尔多够到一个"的机会。**
在离天花板远的底座上是巨大净收益，在已接近天花板的底座上是纯损失
（`hce1_ctl` 16.00 union 17 → `hce1_perinst` 16.00 union 16）。

这与 `--ce-energy 1` 观察到的形状一致（方差塌到 ±0.41，union 卡在 14），
是同一个权衡：**稳定收割 vs 随机探索**。

### 17.6 mnist 的 18 个 SAT 没有真正的难例

按内容核对（`results/abcrown_2022_mnist_fc_results.csv`）：

```

```

**漏掉的那条不是难例，只是确定性路径恰好够不到。**（真正三方确认的难例在 cifar：
`medium#11`，abcrown 判 SAT、PGD 2000 restarts 攻不下、fuzzer 30x6 次一次没破。）

### 17.7 反例数量作为指标的问题

论文用 violations 当主指标。冗余度实测：

```
cifar baseline          每攻破 1 个实例产出 477 个反例，最好的臂 60 个
tinyimagenet baseline   30x30 组 2,121 个反例 -> 1 个 distinct 实例
```

作为**吞吐代理**可接受（violations/秒衡量单位时间做了多少工作），
作为**发现量**有缺陷，而且论文按组聚合上报（5.1 节 "All violation counts are
aggregated across all model groups G"），冗余度在合计数字里看不见。

**对修复而言相关的量同样是 distinct 而非总数**：9.3 节测到反例散布在几百个互不
相同的激活区域、与非反例交织、判别性签名只占 0.04-0.5% 的维度**且随样本量增多而消失**
（`inst 26` 188 个反例签名只有 9 维，`inst 14` 1 个反例有 449 维）。
所以同一实例的第 2 到第 477 个反例，对验证无用，对故障定位的边际价值也接近零。
（**这一段关于修复的推断没有实验支持**，是从 9.3 的几何测量外推的。）

### 17.8 待做

- **`--ce-energy 0`**（跑中）：反例彻底失去特权。支持它的理由是
  distinct 数的是实例，而反例按定义属于已攻破的实例，边际价值为零；
  反对的理由是 16.5 节的倒 U 把最优区间放在 CE 占质量 46-66%，归零会冲过右端。
- **只在未攻破实例上轮转** —— 这条线的终点形态，把全部预算压到还没解决的问题上。
  实现不难（`select()` 里跳过已在 `distinct_instances_hit` 的实例），
  但引入"用结果指导搜索"的耦合，会不会让指标失去意义需要先想清楚。
- **轮转只在 mnist 上测过。** cerepl 是四个 benchmark 全正的（+3.83 / +70.00 /
  +4.93 / +10.80），轮转要跟上必须补 tinyimagenet（B=200 单组，baseline 只有 13%
  天花板，未攻破实例每 rep 只分到 3.6 次抽取）、safenlp（B=145，cerepl 在那里是 +70）
  和 cifar（B=100）。**tinyimagenet 是最该补的一个。**

### 17.9 `--ce-energy 0`：反例彻底失去特权

`energies = admitted*10 + violation*0`，clamp 到 0.1。反例仍然入库（门是
`violation | admitted`，没变），但不新颖的反例掉到 **0.1**，比一条初始种子（1.0）
还轻 10 倍。不需要改代码；cerepl 在这个设置下仍然工作，因为父代判据读的是
记录下来的 `_is_ce` 标志而不是能量阈值（14 节那处改动正是为此）。

支持它的理由：`distinct` 数的是**实例**，而反例按定义属于已攻破的实例，
边际价值为零；retain 效应（3.3 节，safenlp large 组 100%）意味着抽到反例
大概率只是再生产同实例的冗余反例。

**实测它和每实例轮转几乎持平**：

```
coverage 底座      5.00 → 12.67 (ce0)   vs  13.00 (轮转)
state+hpgd 底座    7.33 → 15.33 (ce0)   vs  16.67 (轮转)
```

而两者的机制指标是**互补**的：

```
ce0     抽中 CE 概率 99.4% → 66.4%（coverage）/ 91.4% → 16.4%（state）
        但 Gini 只从 0.95 降到 0.78-0.80，有效实例 1.3 → 4.3-5.0
轮转    抽中 CE 概率几乎不变（99.4%）
        Gini 0.95 → 0.00，有效实例 1.3 → 30.0
```

**一个几乎不改分配却拿到同样结果，一个把分配做到理论最优却没多拿多少。**

这否定了 16.5 节倒 U 曲线的一种读法：我曾预测 ce_energy 0 会冲过最优区间
（46-66%）的右端而变差，实测没有。所以那条曲线右端的下降**不是反例被稀释造成的**，
而是 admitted 档吃光了质量（tinyimagenet 的 `state_ce1_cerepl`：admitted 占 98.48%，
初始种子只剩 0.21%）。**问题始终是"某一档吃光质量"，不是"反例太少"。**

### 17.10 三种干预两两不叠加，且含轮转的叠加为负

```
组合                            结果     单项最优    叠加效应
cerepl + ce0（state）          13.00     11.40       +1.60
cerepl + ce0（state+hpgd）     15.67     13.60       +2.07   union 18（满）
cerepl + 轮转（coverage）      12.67     13.00       −0.33
ce0    + 轮转（state+hpgd）    16.00     16.67       −0.67
```

**含"轮转"的叠加全为负，不含轮转的叠加全为正。**

因为轮转直接把有效实例推到 30.0（理论上限），此时别的干预只剩副作用；
而 cerepl（2.2）与 ce0（4.3-5.0）都只是部分改善，叠到 7.7 仍在收益曲线上升段。

**如果三者修的是不同的东西，至少该有一对能与轮转叠加 —— 实测没有。
所以 lane 分配是唯一的瓶颈，三个开关是它的三种干预点。**

### 17.11 收益曲线：过了 5 个有效实例就饱和

> **已被 18.3 订正**：饱和点随 B 移动，这一节只对 B=30 成立。

```
有效实例   1.3–1.4  →  2.2   →  4.3–5.0  →  7.7  →  30.0
distinct   5.0–7.3    10.3     12.7–15.3   13.0   13.0–16.7
增量                  +5.3      +2.3       +0.3    +0.3 ~ +1.3
```

**瓶颈是"有没有被完全饿死"，不是"分得均不均"。**
从"一个实例吃光"到"五个实例分"拿到绝大部分收益，再推到 30 只多 0.3-1.3。

**（重要限定）这是在 mnist 上得出的，而 mnist 从未真正饿死过**：它最饿的实例每 rep
仍有 35-40 次抽取。tinyimagenet 的 B=200 对 200 个实例，最饿的只有 3.6 次，
差一个数量级 —— 17.13 节的 600 秒实验就是去测那个区间。

## 18. tinyimagenet 600 秒：饥饿区间的决定性实验（2026-08-30 晚）

**这一节是全项目最强的结果，也订正了第 17 节的主结论。**

跑法：`tinyimagenet_v2`，单组 B=200 对 200 个实例（所以 `--select-per-instance`
每批就是一个精确排列），600 秒/组，每臂 2 次，天花板 38（abcrown 2025，200/200 全判定）。
目录 `results/bench_tinyimagenet_v2_600s/`，60s 与 1200s 两批未动。

### 18.1 有效实例数单调决定一切（**仅限同一底座内** —— 见 18.8）

| arm | distinct | per-rep | union | 占天花板 | violations | 冗余 | 有效实例 | Gini | 最饿实例 |
|---|---|---|---|---|---|---|---|---|---|
| baseline | 1.50 | [1,2] | 2 | 3.9% | 7,768 | **5,179** | **1.14** | 0.954 | **0** |
| base_ce0 | 19.00 | [18,20] | 21 | 50.0% | 6,389 | 336 | 2.55 | 0.809 | 3.5 |
| covce1cer | 28.50 | [26,31] | 31 | 75.0% | 1,912 | 67 | 59.96 | 0.479 | 13.5 |
| **base_pi** | **34.00** | [34,34] | 34 | 89.5% | 769 | 23 | **199.89** | 0.013 | 40.5 |
| **covce1cer_pi** | **34.50** | [35,34] | **35** | **90.8%** | 678 | **20** | 199.89 | 0.012 | 42.0 |

**有效实例数排序 = distinct 排序，四个档位无一例外，冗余度反向单调（5,179 → 20，225 倍）。**

> **限定（18.8）**：上表五个臂全是 coverage 底座。换成 state 底座后这条单调关系立刻断裂
> （`statebase` eff 5.05 → distinct 7.50，而 `base_ce0` eff 2.55 → 19.00，分配更均匀但结果更差）。
> **eff 只测分配均匀度，不测种子质量，两者独立。**

`baseline` 有 **18 个实例整轮 0 次抽取**，一个实例吃掉 94.5% 的 lane。
这是全部五个 benchmark 里饥饿最深的一处，也正是要测的区间。

**`base_pi` 用一半预算超过 1200 秒全部臂的最好成绩**（`cov_ce1_cerepl` 30.40，
还开了两个开关）。它一个能量开关都没开。

### 18.2 论文主指标沿这条线反向单调

```
             violations    distinct
baseline       7,768 ↑       1.50 ↓
base_ce0       6,389         19.00
covce1cer      1,912         28.50
covce1cer_pi     678 ↓       34.50 ↑
```

**发现量涨 23 倍的同时，论文的主指标掉 11 倍，符号完全相反。**

原论文（arXiv:2606.25239）的 headline 是 `up to 40X higher throughput and 4X more
violations than the sequential baseline`。查过全文，那个 "sequential baseline"
**不是任何已发表工具，是作者自己框架跑 B=1**：

> "We compare against a controlled baseline that captures the canonical
> one-input-per-iteration fuzzing paradigm underlying DeepHunter (Xie et al., 2019),
> which does not have an official open-source implementation. We implement this
> baseline within our framework (where B=1 with fixed scalar η, as in Table 1)."

TensorFuzz 被明确排除（"unmaintained since 2019"）。**Table 4 / Figure 6 只有
Seq-Fixed / Batch-Iso / Batch-Ani 三个自家配置，没有任何外部工具。**

**我们所有表里的 `baseline` = 论文的 Batch-Ani，即它最强的一格**（runner 文件名
`paper_cifar100_batch_ani.py` 即此意）。写论文时必须改名成 `ACT (as published)`，
否则审稿人会当成弱对照。

### 18.3 订正 17.11：饱和点随 B 移动

17.11 写的是"过了 5 个有效实例就饱和"。**那是小批次的伪影。**

```
              有效实例/B      distinct/天花板
mnist  ce0     5.0/30 = 0.17       70%
mnist  轮转   30.0/30 = 1.00       72%    <- 看似等价
tiny   ce0     2.6/200 = 0.013     50%
tiny   轮转  199.9/200 = 1.00      90%    <- 差 15 个实例
```

**`--ce-energy 0` 给出的有效实例数是个与 B 无关的常数（2-5）；轮转给出的是 B 本身。**
B=30 时常数 5 已占 17%、越过饱和点，所以两者看起来殊途同归 —— 那是巧合。
B=200 时同一个常数只占 1.3%，立刻不够。

**保留的正确版本：需要的有效实例数随 B 增长；只有直接规定 lane 分配的机制能跟上，
靠能量定价间接拉匀的机制跟不上。**mnist 的"三条路殊途同归"作废。

### 18.4 CE 占质量作为解释变量被淘汰

```
covce1cer_pi   CE 占质量 38.90%   distinct 34.50
base_pi        CE 占质量 99.68%   distinct 34.00
```

**CE 占质量差 2.6 倍，结果差 0.5（噪声内）。**轮转打开之后 CE 档占多少质量不再重要
—— 它决定的是"实例内部挑哪一行"，而不是"哪个实例拿到 lane"。

这否定了 11/12/16 节反复用的那条解释（"效应量随 CE 档垄断深度排序"）。
**正确的说法是 CE 占质量此前一直是 lane 垄断的代理变量，直接测 lane 分配之后它就失去解释力。**

### 18.5 轮转饱和之后其余开关无增量，跨两个 benchmark 成立

```
mnist   cerepl + 轮转   12.67  vs 轮转 13.00      -0.33
mnist   ce0    + 轮转   16.00  vs 轮转 16.67      -0.67
tiny    ce1+cerepl+轮转 34.50  vs 轮转 34.00      +0.50   (n=2，噪声内)
```

三次叠加全部落在 ±0.7 内。**lane 分配是唯一瓶颈，三个开关是它的三种干预点** —— 
第 17.10 节的结论在 B 大 6.7 倍、饥饿深两个数量级的 benchmark 上重现。

差别是代价：mnist 上轮转把并集锁死（per-rep 全等于 union）是净损失，
因为那里已接近天花板；tinyimagenet 上 `base_pi` 同样锁死（[34,34] union 34），
但 34 已是 89.5%，锁死的代价被收益淹没。**17.12 的预测第一次在大 B 上被证实。**

### 18.6 掩码口径的订正（影响 HPGD 全部结论）

默认 `--unstable-mask row0`（`paper_cifar100_batch_ani.py:597`），**跑过的臂无一改过**。
所以历次日志里的 `[state] unstable neurons: n/N` 都是**实例 0 的盒子**，不是组的并集：

| benchmark | 组 | ReLU 总数 | 实例 0 不稳定 | 占比 | flip=10 占比 |
|---|---|---|---|---|---|
| tinyimagenet | 单组 | 172,296 | 1,112 | **0.6%** | 0.90% |
| cifar100 | small | 55,460 | 951 | 1.7% | 1.05% |
| cifar100 | large | 286,820 | 3,225 | 1.1% | 0.31% |
| mnist | 256x2 | 512 | 56 | 10.9% | **17.9%** |
| mnist | 256x4 | 1,024 | 685 | 66.9% | 1.46% |
| mnist | 256x6 | 1,536 | 1,184 | 77.1% | 0.84% |
| safenlp | small/large | 128 | 70 / 93 | 54.7% / 72.7% | 14.3% / 10.8% |

（§1.3 量过：cifar 逐实例掩码规模与 row0 相近 0.9-1.0 倍，但成员只有 9-12% 重叠，
跨实例离散度大 —— large 组 1369-3764。所以这些数字可用作规模刻画，不可用作
"HPGD 在操作哪些神经元"的刻画。）

**掩码稠密度不能解释 HPGD 的跨 benchmark 符号**：tinyimagenet 最稀疏（0.6%）
但有 cerepl 时为正（+0.80），cifar 居中却两种情况都负，safenlp 最稠密却在无 cerepl 时最负（-4.40）。
用 flip/unstable 排序也不成立。**13.3 节那条组内相关只在 mnist 一次运行内成立，不可外推。**

**唯一站得住的分组仍是"调度修没修"**：

| benchmark | statebase → statehpgd | statebase_cerepl → statehpgd_cerepl |
|---|---|---|
| cifar100 | −0.40 | −0.73 |
| safenlp | −4.40 | **+1.00** |
| mnist | +1.30 | **+2.20** |
| tinyimagenet | −4.00 | **+0.80** |

**无 cerepl 三负一正，有 cerepl 三正一负。**掩码这个竞争解释被排除后，这条更干净了。

而且**所有 HPGD 对比都是在 row0 下跑的，命中率只有 9-14%**（`per_instance` 是 72-76%，§1.3）。
即论文里 HPGD 的成绩是被人为削弱的版本。

### 18.8 底座 × 调度的 3×2（六格，同预算同 n）

`baseline` / `base_pi` 已在 18.1，补齐 state 与 state+hpgd 两行，全部 600 秒 × 2 次。

| 底座 | 无轮转 | 有轮转 | 轮转增益 |
|---|---|---|---|
| coverage | 1.50 | 34.00 | **+32.50** |
| state | 7.50 | **35.00** | **+27.50** |
| state+hpgd | 7.50 | 34.00 | **+26.50** |

```
底座增益   无轮转:  state +6.00   hpgd  0.00
           有轮转:  state +1.00   hpgd -1.00
```

**① 轮转在三个底座上都值 +26.5 ~ +32.5，与底座无关。**全表唯一大到无可争议的效应。

**② state 的 +6.00 在调度修好后塌成 +1.00 —— 第四个 benchmark 确认同一条规律**
（cifar +3.20/+3.83 → −0.60/+1.00，第 12.9 节）：**state 准入的收益随池子被解除垄断而趋于零。**

机制直证：`statebase_pi` 比 `base_pi` 多 admit 了 4,500 行（rows 5,522 vs 974，
CE 行占比 18.3% vs 79.0%），**结果只差 +1.00**。轮转把实例配额钉死之后，
池子里多几千行只影响"实例内部挑哪一行"，而能量排序本来就会挑最好的那行。
**多出来的行买不到东西。**

**③ HPGD 在 tinyimagenet 上 ≤ 0**：600s 是 0.00 / −1.00（n=2），
1200s 是 statebase 9.00 → statehpgd 5.00（n=5，−4.00）。合并读数为无效。
细节：`statehpgd` 的 eff 3.63 低于 `statebase` 的 5.05 —— **HPGD 让分配更不均匀**
（落点更集中），但 distinct 相同。

**限定**：三个 `_pi` 臂全落在 34.00-35.00，n=2，距天花板只剩 3-4 个实例。
**这个区间分辨不出底座差异，不能读成"底座无用"。**要分辨得回到 60s 预算重跑这三格
（那里 coverage 底座在 4.50 上下，空间充足）。

### 18.9 eff 的解释力边界：分配均匀度 ≠ 种子质量

18.1 那条单调关系在换底座后立刻断裂：

```
statebase   eff  5.05  ->  distinct  7.50     分配更均匀，结果差 2.5 倍
base_ce0    eff  2.55  ->  distinct 19.00
```

`statebase` 造出约 2,000 行"新颖但无用"的非反例行（rows 7,199，CE 行占比 81.1%，
对照 baseline 的 97.4%），抽取确实分散到更多实例（eff 1.14 → 5.05），
**但落在了质量更低的种子上**。

**结论：eff 只测"谁拿到 lane"，不测"拿到之后能不能用好"。两者独立。**
第 18.1 的单调关系只在同一底座内成立；17.11 的收益曲线同理（也是单底座内测的）。

这对论文是好消息 —— 此前一直把"调度"和"种子质量"混在一起讲，
现在有了两个可独立测量的维度：eff 测前者，同 eff 下的 distinct 差异测后者。
**`base_pi` / `statebase_pi` / `statehpgd_pi` / `covce1cer_pi` 四格 eff 全部锁定在
199.89-199.92，正是为后者准备的受控对照**（只是这次撞了天花板，需要降预算重做）。
